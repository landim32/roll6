Corrections to the auto-generated sections above:

- **Project Structure** — there is no root `tests/`. The real layout is `backend/` (`Roll6.sln`:
  `Roll6.DTO` → `Roll6.Infra.Interfaces` → `Roll6.Domain` → `Roll6.Infra` → `Roll6.Application` → `Roll6.API`,
  plus `Roll6.Mcp` and `Roll6.Tests`) and `frontend/` (React SPA). Design artifacts live in `specs/<NNN-feature>/`.
- **Commands** — backend: `cd backend && dotnet build Roll6.sln`, `dotnet test`,
  `dotnet ef migrations add <Name> --project Roll6.Infra --startup-project Roll6.API`,
  `dotnet ef database update --project Roll6.Infra --startup-project Roll6.API`, `dotnet run --project Roll6.API`.
  Frontend: `cd frontend && npm install`, `npm run dev`, `npm run lint`, `npm test`, `npm run build`.
  Never run `docker`/`docker compose` on the dev machine (constitution, Principle II).
- **Code Style** — not just "standard conventions": see constitution Principles III–VI. Directory casing is
  load-bearing (`Contexts/`, `Services/` uppercase; `hooks/`, `types/`, `lib/`, `components/` lowercase);
  every DTO property needs `[JsonPropertyName("camelCase")]`; HTTP responses are the DTO on success and
  `ProblemDetails` on error (no `sucesso`/`mensagem`/`erros` envelope — the `react-architecture` skill is
  outdated on this point); frontend uses `interface` over `type`, arrow functions, `const`, and **no `enum`**
  (`tsconfig` sets `erasableSyntaxOnly`).

New backend entities/patterns follow `.claude/skills/dotnet-architecture/SKILL.md`; new frontend
Types/Service/Context/Hook follow `.claude/skills/react-architecture/SKILL.md` (read them from disk — they are not
registered as skills in this session).
