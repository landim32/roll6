# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project status

The backend (feature `001-backend-core-entities`) is implemented in `backend/`; the frontend does not exist yet. There is no PostgreSQL or Docker on the dev machine, so migrations are generated but must be applied against a reachable database (`dotnet ef database update`, see below). Image URLs need S3 credentials (standard AWS env vars/profile) because reads generate presigned URLs.

## Product intent

Roll6 is a deliberately **simple** Roll20-style virtual tabletop web app. Scope:

- User login.
- Users create adventure maps.
- Users upload images (map backgrounds, token art).
- Users create tokens and place/move them on the map.
- Maps use a grid built with the hexagon algorithms from Red Blob Games: https://www.redblobgames.com/grids/hexagons/

Keep it simple — resist adding Roll20 features (dynamic lighting, character sheets, macros, chat, etc.) unless a spec explicitly asks for them.

## Constitution

`.specify/memory/constitution.md` is binding and overrides agents/skills when they conflict. Read it before planning or implementing. Highlights that are easy to get wrong:

- New entities MUST be built with the `dotnet-architecture` (backend) and `react-architecture` (frontend) skills — don't hand-roll those patterns.
- Frontend: Bootstrap 5 (not Tailwind/shadcn, even though the `ux-designer` agent defaults to them), Context API only (no Redux/Zustand), Fetch API for new services, `interface` over `type`, `VITE_` env vars.
- Directory casing is load-bearing: `Contexts/`, `Services/` uppercase; `hooks/`, `types/` lowercase.
- Never run `docker` / `docker compose` locally.
- PostgreSQL via EF Core only; snake_case tables/columns, `ClientSetNull` deletes (never Cascade).
- Auth token is stored in localStorage (never cookies); sensitive controllers need `[Authorize]`.

## Hex grid rules (Red Blob Games, constitution Principle VII)

All grid math must follow the Red Blob Games hexagon guide rather than ad-hoc formulas:

- Hexes are always **flat-top** in a rectangular grid (`grid_width` columns × `grid_height` rows, odd columns shifted half a hex down — the guide's "odd-q" offset layout).
- Positions are **stored as column/row** (`x`, `y`). For distance, neighbors, lines and ranges convert to axial (`q = x`, `r = y - (x - (x & 1)) / 2`), compute with the cube/axial formulas, and convert back (`x = q`, `y = r + (q - (q & 1)) / 2`). Never store `q`/`r`/`s`.
- Hex↔pixel conversion goes through a `Layout` (size, origin) as described in the guide's "Implementation" section.
- Pixel→hex uses fractional hex + **cube rounding** (`hex_round`); never round q/r independently.
- Distance, neighbors, line drawing (lerp + round), and ranges come from the guide's cube/axial formulas.
- Keep the hex math in one pure, framework-free module (frontend) so it can be unit-tested and, if the backend needs grid logic, mirrored 1:1 in C#.

### Conventions

- **Auth**: local users (`users`, `PasswordHasher` PBKDF2); login issues our own JWT (`Authorization: Bearer`), valid **90 days** (`Jwt:ExpirationHours` = 2160 in every `appsettings*.json`; the frontend logs out at the login response's `expiresAt`). Controllers take the owner id from the JWT `sub` (`CurrentUserId`) and pass it to services, which enforce ownership.
- **Errors**: services throw domain exceptions; every action is `try { } catch (Exception ex) { return HandleException(ex); }` (`ApiControllerBase`): `DomainValidationException` → 400 `ValidationProblemDetails`, `UnauthorizedAccessException` → 403, `KeyNotFoundException` → 404, `ConflictException` → 409, else `StatusCode(500, ex.Message)`. Never throw `InvalidOperationException` for business conflicts (EF Core throws it on connection failures).
- **Responses**: DTO directly on success, `ProblemDetails` on errors (constitution v3.0.0) — ignore the `sucesso`/`mensagem`/`erros` envelope of the `react-architecture` skill. Paged lists: `PagedList<T>` + `PageQuery` (`page`, `pageSize` ≤ 100, `search`).
- **Persistence**: `Roll6Context` configures every table inline in `OnModelCreating`; one migration per change, plus an incremental script `database/migrations/NNN-*.sql` and regenerated `database/roll6.sql`. FKs are `ClientSetNull`, never cascade — services delete dependents first. Npgsql legacy timestamp switch is on (`timestamp without time zone` holding UTC). Int/bool columns with DB defaults need `HasSentinel` so explicit zeros/false are written. Services use the registered `TimeProvider` for "now".
- **Realtime**: domain services publish through `IRealtimeNotifier` (last constructor parameter) **after** the write succeeds (see 017).
- **MCP**: adding or changing an endpoint requires its tool (see 020); coverage tests pin the counts.

### Images and files

- Stored in DigitalOcean Spaces through the AWS S3 SDK (`S3:ServiceUrl` = `https://{region}.digitaloceanspaces.com`, `S3:Region` = `us-east-1`, `ForcePathStyle` false; empty `ServiceUrl` = AWS S3; custom endpoints disable default checksums and chunked uploads). Upload via `POST /api/image` (`IImageStorageAppService`) to `{S3:Folder}/{guid}.{ext}` (`S3_FOLDER`, default `roll6`); entities store only `{guid}.{ext}` (`Guard.ImageFileName`), reads return presigned URLs. Stored files are **write-once** and never overwritten or deleted (so several rows may reference one object).
- The bucket sends no CORS headers: the map-share canvas reads images through `GET /api/image/file/{fileName}` (`[Authorize]`, `{32-hex}.png|jpg|webp`, streamed via `OpenAsync`; excluded from MCP); `lib/mapSnapshot.loadImage` extracts the name with `storedImageName`.
- Sheet files (022): `POST /api/document` (`DocumentController` → `IImageService.UploadDocumentAsync`): PNG/JPEG/WebP or PDF (`%PDF-`), ≤ 10 MB, stored untouched → `{ fileName, url, type: image|pdf }`. `characters.sheet_file` (`Guard.SheetFileName`, `.pdf` only there), `sheetFile` on `POST`/`PUT /api/character` (omitted on PUT = removed), read as `sheetFileUrl`/`sheetFileType` (`SheetFiles.TypeOf`).

### Characters and campaigns

- Campaign characters (005/008): `GET /api/character/search` (any logged user) returns only `CharacterSearchInfo` (name, image, owner) — never sheet/stats. `GET /api/campaign/{id}/character` = master/approved only; players read their own statuses via `GET /api/campaigncharacter/mine`; `DELETE /api/campaigncharacter/{id}` (master) removes the participation only. `CampaignCharacter.RequestAccess(..., autoApprove)` approves directly in open campaigns and when the requester is the master.
- Vitals, status, campaign sheet (009/010/032): `characters.life`/`energy` are **totals** (≥ 0); the character has no status. Each participation holds `current_life`/`current_energy` (≤ total, may be ≤ 0; life does not set posture), `character_status` (free text ≤ 260, `CharacterStatus` — not the participation `Status` enum) and `sheet`/`sheet_file` = the **campaign sheet** ("Ficha da Campanha"). `CampaignCharacter.ResetFrom(character)` runs whenever a participation is created or becomes Approved (the service passes the `Character` into each transition): currents = totals, copies `Sheet`/`SheetFile`, clears the status, standing posture, `CurrentMove` = `Character.Move`. That is the only copy point — no re-sync. The campaign file copy is a second reference to the same object. `ChangeSheetFile`: null = keep, `""` = remove, a name = replace (unlike `CharacterInsertInfo.sheetFile` where null removes). Turn-log diff key stays `"notes"` (printed "Ficha da campanha alterada"), plus `"sheetFile"` ("Ficha em arquivo alterada"). `CharacterService.UpdateAsync` clamps currents (`ClampVitalsAsync`).
- Deslocamento (037): `campaign_characters.current_move` (≥ 0, no max) = movement points a **player** may spend per turn with that character on the campaign's maps. Changed by owner or master via optional `currentMove` of `PUT /api/campaigncharacter/{id}` (`ChangeMove`, null = keep, turn key `"currentMove"`, "Deslocamento de X para Y") or `process_turn`; `CharacterService.UpdateAsync` moves it with a changed `Move` only where it still equalled the old one (`FollowMoveAsync`). `MapTokenService.EnsurePlayerMoveAsync` checks the cost against it; character pieces return it as `MapTokenInfo.move`; `characterMove` is the permanent move. The master is never limited.
- Permissions: `GET`/`PUT`/`DELETE /api/character/{id}` are **owner-only** — the master never changes the character itself. `PUT /api/campaigncharacter/{id}` (`CampaignCharacterUpdateInfo` → `UpdatePlay` + `ChangeSheetFile`, Approved only; optional `tokenId` saved on the character via `Character.ChangeToken`, null = keep; optional `sheetFile`) = owner or master. `GET /api/campaigncharacter/{id}` (`CampaignCharacterDetailInfo`: campaign `sheet`/`sheetFile…`, read-only `characterSheet`, `characterTokenName`/`characterTokenImageUrl`) = owner, master or any approved participant. Lists carry `characterStatus`/`characterMove` but not the sheet (they are polled).
- Transfer (021): `POST /api/character/{id}/transfer` (`{ email }`, owner only, 204) changes only `characters.user_id` through a conditional update (`CharacterRepository.TransferAsync`, `WHERE user_id = owner`; 0 rows → 409) — everything else points to the character and reads the current owner. Errors 400 (invalid / own e-mail), 404 `Usuário não encontrado.`; publishes `party.changed` + `mapTokens.changed` per campaign and the former owner leaves groups where they lost access.
- Maps are soft-deleted (`MapStatus.Deleted`); names from `MapRepository.InsertWithNextSequenceAsync` (unique index campaign + model + sequence). Deletes of tokens/map models/campaigns in use are blocked in the services; campaign deletion removes its Deleted maps inside `IUnitOfWork`.
- Slugs (029): `campaigns.slug`/`maps.slug` `varchar(100)`, globally unique (`ix_campaigns_slug`, `ix_maps_slug`), required and **immutable** — `AssignSlug` only on insert (`Slug.From` + `Slug.NextFree`, retry once on `UniqueViolation`). `GET /api/campaign/slug/{slug}` = any logged user (404 `Campanha não encontrada.`); `GET /api/map/slug/{slug}` = master or approved (Deleted → 404 `Mapa não encontrado.` before the access check; no access → 403). `GET /api/campaign/table` = campaigns the user masters or plays (approved) + the current map (`CampaignTableInfo`); `maps` (`TableMapInfo`, current and active maps) is filled only for campaigns the caller masters (078), `[]` for players. `GET /api/campaign/{id}/turn/narration?turnNo=` (master or approved) joins the `Narration` entries of that turn — or, without `turnNo`, of the greatest `turn_no < current_turn` that has one — with `\n\n`; `finishedAt` = last entry's `created_at` (null on the turn in progress); none → 204.
- Campaign status (049): `campaigns.status` (`CampaignStatus` 1 Preparing, 2 Active, 3 Paused, 4 Finished; DB default 2; `CreateAsync` starts as Preparing). `PUT /api/campaign/{id}/status` (master, 400 `status` outside 1–4, same value = no event, else `campaign.changed`). Rules on `Campaign`, both 409 "A campanha está em preparação/pausada/finalizada.": `EnsurePlayable()` (Active only) guards act, reset, finish, process, set-current, convert (`canConvert` null), poke, request access / invite / approve / accept invite; `EnsureMapEditable(isMaster)` (Active, or Preparing for the master) guards every `MapTokenService` write, `MapNpcService` writes and `MapService.CreateAsync`. Never gated: the conversation chat, participation updates, deny/decline/remove, campaign NPCs, map rename/archive/delete, current map, plan, admin turn fixes, map models.
- Campaign flags, all master-only, any status, same value = no event, else `campaign.changed`, carried by `CampaignInfo`/`CampaignTableInfo`:
  - Free mode (054): `campaigns.free_mode` via `PUT /api/campaign/{id}/free-mode`. **Switching never touches the turn.** While on, decided after `EnsurePlayable`/`EnsureMapEditable`: `MoveAsync` records **no** Movement (no one-move rule, no `turn.changed`) and `EnsurePlayerMoveAsync` keeps only ownership (no Deslocamento cost; `EnsureFits` still applies); `FinishAsync` finishes as if `force`; `ResetAsync` cancels Actions only (Movements untouched). Actions are still one valid per turn (073). Leaving free mode is refused (409 `CampaignService.FreeModeOverlapMessage`, ≤ 300 chars, naming the groups — "Não é possível sair do modo livre: Aria e Borin; … estão no mesmo hex.") while pieces overlap (`IMapTokenService.ListOverlapsAsync`, pure `Occupancy.Overlaps()`); `CampaignService` takes `IMapTokenService` as last constructor parameter.
  - Pending notice (072): `campaigns.pending_notice` (default true; EF `HasDefaultValue(true).HasSentinel(true)`) via `PUT /api/campaign/{id}/pending-notice` — only decides whether the chat shows who still owes a play; changes no rule.
  - GM mode (096): `campaigns.gm_mode` via `PUT /api/campaign/{id}/gm-mode` (on → the GM check, off → stops the campaign's run). See below.
  - Picture (090): `campaigns.image` (`Campaign.ChangeImage`, `Guard.ImageFileName`), `image` on `CampaignInsertInfo`, `PUT /api/campaign/{id}/image` (`CampaignImageInfo`), `image`/`imageUrl` on `CampaignInfo`, `imageUrl` on `CampaignTableInfo`.
- Campaign plan (018): `campaign_plans` (title ≤ 260 + markdown `varchar(50000)`), **master only** for everything (`GET /api/campaign/{id}/plan` lists without descriptions; `GET`/`POST`/`PUT`/`DELETE /api/campaignplan`). Images in the text are stored as `roll6-image:{guid}.{ext}` (presigned URLs expire); the detail returns `imageUrls` (`CampaignPlan.ImageFileNames()`). Campaign deletion deletes its plans.

### NPCs

- NPCs (013): `Npc` = owner's library entry (required `TokenId`, same limits as `Character`, optional `status` ≤ 260, initial `posture` (036, default standing, omitted on PUT = standing)); `/api/npc` CRUD owner-only, delete refused while in a campaign. `CampaignNpc` makes one of the master's own NPCs available in a campaign (unique per campaign; `POST`/`DELETE /api/campaignnpc` master only; `GET /api/campaign/{id}/npc` master + approved). `MapNpc` = one **instance** on a campaign map with its own name, status, posture and **current** life/energy (`current_life`/`current_energy`, 026: start at the NPC's totals, may go ≤ 0, never above them; lowering totals clamps via `IMapNpcRepository.ClampVitalsAsync` + `mapTokens.changed`). `POST /api/mapnpc` creates it **and** its piece (`MapToken.PlaceNpc`) in one transaction, linked by `map_tokens.map_npc_id` (unique). Pieces with `MapNpcId` show the occurrence's data (the piece's own life/energy/status stay 0); every `MapTokenInfo` comes from `MapTokenService.MapToDtoAsync` (+ NPC totals `totalLife`/`totalEnergy`, move, sheet — the piece's own sheet wins). Master writes; `GET /api/map/{id}/npc` master + approved. Tokens used by NPCs can't be deleted.
- Instances (051/052): `MapNpc.NextName` = NPC name, then "{name} 2", "{name} 3"… (smallest number free among active instances on that map). `map_npcs.current_move` (copied from `npcs.move`; `MapNpcUpdateInfo.currentMove` null keeps, `process_turn` `npcs[].currentMove`, key `"currentMove"`; follows a changed NPC move only where untouched — `FollowMoveAsync`). **Removal is soft** (`map_npcs.removed_at`, `MapNpc.Remove`): `DELETE /api/mapnpc/{id}`, deleting an NPC piece and `DELETE /api/campaignnpc/{id}` delete the pieces and mark instances removed, **keeping every turn entry** (`ListByIdsAsync` returns removed rows, the map/campaign lists skip them; update/delete of a removed instance → 404). `NpcService.DeleteAsync` hard-deletes leftovers (`DeleteByNpcAsync`). `CampaignNpcInfo.mapNpcCount`. `MapNpcInsertInfo.x`/`y` optional: without them the piece goes to the **free hex nearest the middle** (`Occupancy.FirstFree`; none → 409 "Não há um hex livre para a peça neste mapa.").
- Categories and allies (071): `campaign_npcs.category` (`NpcCategory` 1 Inimigo default, 2 Neutro, 3 Aliado) and `master_campaign_character_id` (FK `fk_campaign_npc_master`), per campaign. `PUT /api/campaignnpc/{id}` (master, any status) → `CampaignNpc.Classify`: only an ally may have a master (400 `masterCampaignCharacterId` "Só aliados podem ter um personagem-mestre."), an approved participation of the same campaign; another category clears it; publishes `campaignNpcs.changed` + `mapTokens.changed`. `MapTokenInfo` of NPC pieces carries `npcCategory`/`commanderUserId`. Pure `Domain/Npcs/NpcCommand` decides the commander: the master, or the **current owner** of an ally's approved master character (`NpcCommandLoader`). The commander may act/reset (403 "Apenas o mestre ou quem comanda o aliado age com este NPC."), move within `CurrentMove` outside free mode, set the posture, and `PUT /api/mapnpc/{id}` life/energy/status/posture only (name or Deslocamento → 403 "Apenas o mestre altera o nome e o Deslocamento do NPC."). Turn entries keep the instance as actor, the commander as author. `ICampaignNpcRepository.ClearMasterAsync`/`ClearMasterByCharacterAsync` run before deny/remove of the participation and before a character delete.

### Turns

- Turns (016): `campaigns.current_turn` (starts at 1) + `turns` log; exactly one of `character_id`/`npc_id` (map NPC entries keep `map_npc_id` — each instance has its own turn). `MapTokenService.MoveAsync` records the Movement (before/after) for character/NPC pieces in the same transaction; a second move in the turn → 409 (objects are free). Read = master or approved. `POST /api/turn/action` and `/reset` = owner of the approved character, the master or (071) the commander; objects 400. Reset cancels the actor's Actions and deletes/undoes Movements (piece moves back only if the former hex is free); does not clear a repeated action. `POST /api/campaign/{id}/turn/finish` (master) lists characters that owe an action unless `force`. `POST`/`PUT`/`DELETE /api/turn` are master-only and the only way to write an ActionResult.
- Turn log (024): every entry has a required author `user_id`; moves store `moved` (`HexGrid.MovementCost`, also for the master, ignoring pieces when no free path); `TurnType.CharacterUpdate` (4) stores `changes` (`jsonb` `[{ field, before, after }]`, `TurnChange.Diff`), written by the system in the same transaction only when something changed: `CampaignCharacterService.UpdateAsync`, `MapNpcService.UpdateAsync`, `CharacterService.UpdateAsync` (one entry per campaign where approved). Finishing counts only Action. `GET /api/campaign/{id}/turn/summary?turnNo=` (none = in progress) → `TurnSummaryInfo.markdown` from pure `Domain/Turns/TurnSummary` ("## Ações" + "## Posições", markdown escaped).
- Admin (030, `TurnService.Admin.cs`, API + MCP only, master): `POST /api/turn` takes any type in turns `1…current_turn` (future → 400); actor and `mapId` must belong to the campaign. `PUT /api/turn/{id}` (`TurnUpdateInfo`, null = keep) changes text/movement/`changes`/`turnNo`/`mapId` by type (non-applicable field → 400), never type, actor, author or `created_at`. Neither moves pieces nor applies the one-move rule. `PUT /api/campaign/{id}/turn/current` (`{ turnNo, discardLaterEntries }`): same = no-op; forward publishes `turn.finished` (no pending check); back publishes `turn.changed` and → 409 while later turns have **any** entry unless `discardLaterEntries`.
- AI processing (027, `TurnService.Processing.cs`): `GET /api/campaign/{id}/turn/data?turnNo=` (master or approved) → `TurnDataInfo` (approved characters and current-map NPC instances with vitals, status, position; `actions` via `TurnSummary.BuildActions`). `POST /api/campaign/{id}/turn/process` (master) takes `TurnProcessInfo { characters[{characterId,…}], npcs[{mapNpcId,…}], narration }` (optional fields, null keeps), validates the whole batch first (positions on the final state so pieces may swap; error keys `characters[i].field`/`npcs[i].field`/`batch`/`narration`), then in one transaction saves, logs `CharacterUpdate` and `Movement` (no one-move limit) by the master and a `TurnType.Narration` (5, no actor, `description` ≤ 10000; actions ≤ 2000) and **finishes the turn**; publishes `party.changed`, `mapTokens.changed`, `turn.finished`.
- Single action (044/073): **one valid action per actor per turn**, in every mode — `turns.cancelled_at`; the repository's single `Log` filter (every turn rule and read) skips cancelled and deleted rows; `ActAsync` and `ConvertAsync(to: action)` cancel the previous valid Action (`ListValidActionsAsync`) in the same transaction; deleting an action from the chat cancels it (owner or master). Cancelled actions stay in the chat (`cancelled`).
- Off-map actions (080): `POST /api/turn/action` (`TurnActInfo`) takes either `mapTokenId` (character or NPC piece) or `campaignId` + `characterId` (characters only; `ResolveCharacterActorAsync` — current owner with an approved participation, or the master; `map_id` = current map or null); neither/both → 400 `mapTokenId`. `ConvertAsync(to: action)` needs no piece.
- Action target (098): `turns.target jsonb` (`Domain/Models/TurnTarget`, a **snapshot** at declaration, never re-read: hex, `distance` (`HexGrid.Distance` ↔ `lib/hexGrid.distance`) and, with a piece, its id, `kind`, `side` self|ally|enemy|neutral|object and state). `target: { x, y, mapTokenId? }` only with `mapTokenId` as actor (with `campaignId`+`characterId` → 400 `target`). `ResolveTargetAsync`: outside the grid → 400 `target` "O hex está fora do mapa."; the given piece must cover the hex (400 "Não há essa peça nesse hex."), else the greatest `mapTokenId` among covering shapes (`Occupancy.PiecesAt`). `Turn.Action(…, target)` requires a `mapId`; `ToMessage` clears it; convert/admin never set one. Reads: `TurnInfo`/`ChatItemInfo.target` (`TurnTargetInfo` + labels + `text` = `TurnTarget.Describe()`); the summary line appends "→ sobre …"; a masked whispered action drops its target.
- Repeated action (099, `TurnService.Repeat.cs`): `campaign_characters`/`map_npcs.repeated_action` (`varchar(2000)`) + `repeated_action_user_id` (`MapNpc.Remove` clears it); `turns.repeated` (`RepeatSource` 1 Declared, 2 TurnStart). `PUT /api/turn/repeated-action` (`TurnRepeatInfo`, actor like `act`; empty description removes in any status; setting needs an active campaign) → `TurnRepeatResultInfo { active, description, applied }`; if the actor has no valid action yet it is recorded now as `Declared`. `RepeatedActionsAsync` adds one `TurnStart` Action per active repetition (approved participations on the current map, instances on their map, author = who set it, no notices) inside `FinishAsync`, `ProcessAsync` (after the batch) and `SetCurrentAsync` forward (final turn only). `ActAsync`/`ConvertAsync(to: action)` clear it; `process_turn` `clearRepeatedAction`. Both kinds count as acted; `GmTurn.Complete(approved, acted, anyDeclared)` — the GM mode runs only when some valid action is not `TurnStart`.
- Processing notice (101, `TurnService.ProcessingNotice.cs`): `PUT /api/campaign/{id}/turn/processing` (`TurnProcessingInfo { processing, reason? }`, master; start needs `EnsurePlayable`, stop any status; reason ≤ 200 → 400 `reason`) → `{ processingTurn, processingUntil, ignored }`. In memory: singleton `Domain/Turns/TurnProcessingRegistry` (`ITurnProcessingRegistry`, last optional `TurnService` parameter), valid only while it is the current turn and younger than 30 min; finish/process/set-current `Clear` it. Start writes once per turn a `GmNotice` line "O mestre começou a processar o turno N." (`ignored: "gm"` while the GM mode runs that turn); stop writes "O mestre interrompeu o processamento do turno N[: motivo]." (`TurnProcessingTexts`). Event `turn.processing`. Nothing blocked, no push. `AskStatusInfo.processingTurn`/`processingUntil`.
- **Out-of-combat characters owe no action**: `CampaignCharacter.OwesAction()` excludes them from finish's pending list, "Falta…", the poke and the GM check (`ActedAsync`).
- Deleting characters/NPCs/instances/campaigns deletes their turn records first; turn deletions go through `TurnRepository.DeleteWhereAsync`, which clears replies pointing to the rows and deletes their reactions, poll votes/options and whisper targets.

### Map, pieces, posture

- Real-time map (017/048/078): `campaigns.current_map_id` (FK `fk_map_campaign_current`) + `PUT /api/campaign/{id}/current-map` (master) is the **only** thing that changes the current map; only an active map can be current (archived → 400 `mapId`). `MapStatus.Current = 4` marks it (unique partial index `ix_maps_campaign_current`); `SetCurrentMapAsync` keeps status and pointer in step in one transaction (old `LeaveCurrent()` first, new `MakeCurrent()`, then the pointer) and publishes `map.current` + `maps.changed`. `Map.IsPlayable` = Active or Current. `Map.Update` refuses status 4 (400 "Use “Tornar atual” para tornar um mapa atual.") and archiving the current map (400 "Torne outro mapa atual antes de arquivar este."). Deleting the current map clears the pointer.
- Posture and size (031, `MapTokenService.Posture.cs`): `Posture` 1 Standing, 2 Down, 3 OutOfCombat on `campaign_characters.posture` (per campaign) and `map_npcs.posture`; pieces only read it (`MapTokenInfo.posture`/`space`). `PUT /api/maptoken/{id}/posture` (owner/master/commander, NPC master or commander, objects 400) and optional `posture` on `PUT /api/campaigncharacter/{id}`, `PUT /api/mapnpc/{id}`, `process_turn` (null keeps) log change `posture`. ## Frontend layout and commands

**Conventions (do not get wrong)**
- Folder casing is from the constitution, not the `react-architecture` skill: `src/Contexts/`, `src/Services/`, `src/hooks/`, `src/types/`. Services are classes whose private `handleResponse` delegates to `Services/apiHelpers.ts` (`handleApiResponse`: 401 → global logout handler; errors → message from `ProblemDetails`). Responses are the DTO itself — no `sucesso` envelope.
- API base is `VITE_API_URL` (`frontend/.env.local`, template `.env.example`); keep it **empty** so the app calls `/api` on its own origin — the Vite dev server proxies `/api` to `VITE_API_PROXY` (5119 = `dotnet run`, 5000 = homolog container), `/hubs` with `ws: true`, `/mcp` to `VITE_MCP_PROXY` (5129); nginx does the same in Docker. Never point `VITE_API_URL` at the homolog API (no CORS outside Development).
- `tsconfig` has `erasableSyntaxOnly`: no `enum`s — use constants. Prefer `interface` over `type`.
- Icons: only Bootstrap Icons, inlined as SVG components in `components/ui/icons.tsx` (`currentColor`, `size` prop; copy the path from the official SVG). Never emoji/Unicode symbols or per-file icons; icon-only buttons carry `title` + `aria-label`.
- `src/i18n/keys.test.ts` fails when any literal `t('a.b')` key used in the code is missing from `pt-BR.json`.
- Markdown rendered from users or models is always sanitized (`rehype-sanitize`): sheets via lazy `components/ui/MarkdownEditor` (`@uiw/react-md-editor/nohighlight`) / `MarkdownView`; plans via `planMarkdownOptions`; Claude answers via `MarkdownView strict`.
- `three` (0.186) lives only in lazy chunks (3D view, previews, editors); it must never reach the main bundle.

## Roll6.Console bridge and web animation editor (086)

- **`Roll6.Console`** (in `Roll6.sln`, references only `Roll6.DTO`) is a **generic bridge** between the site and the

## Versioning and commit messages

Versions are computed by **GitVersion** (`GitVersion.yml`, `mode: ContinuousDelivery`) in `.github/workflows/version-tag.yml`
on every push to `main`, which tags `vX.Y.Z`; `create-release.yml` then creates a GitHub release **only when the major or
minor number changed** (a patch gets a tag, no release). The increment comes from the commit messages since the last tag
(`commit-message-incrementing: Enabled`); without a matching message `main` still bumps the **patch** (`increment: Patch`).
The project reached **1.0.0** on 2026-10-22 by the user's request: the production commit of v0.67.1 was tagged `v1.0.0`
(with its release) by hand; GitVersion counts from the highest tag, so the next `feat:` is 1.1.0 and the next `fix:` 1.0.1.

| Prefix (start of a line of the message) | Bump | Use it for |
|---|---|---|
| `fix:` (or `patch:`) | patch `1.0.0 → 1.0.1` | **small corrections**: a bug, a wrong text, a broken layout, a deploy/console fix, docs or tests alone |
| `feat:` (or `feature:`, `minor:`) | minor `1.0.1 → 1.1.0` | **a complete feature** — normally one Spec Kit feature (`NNN-…`) delivered |
| `major:` / `breaking:` | major `1.1.0 → 2.0.0` | **only when the user explicitly asks for a major version** — never on our own |
| `+semver: none` / `+semver: skip` | none | a commit that must not move the version |

- The regexes are case-insensitive and match **any line** of the message, body included: never start a body line with
  `major:`, `breaking:`, `feat:` or `fix:` by accident (it would bump that level). Write those words mid-sentence.
- The highest bump among the commits since the last tag wins (a `feat:` and a `fix:` in the same PR → minor). GitHub's
  merge commit ("Merge pull request #N from …") carries the **PR title** in its body, so the PR title counts too: give it
  the same prefix as the commit (`gh pr create --title "fix: …"`).
- Pick the prefix by the size of the change, not by the branch name: a Spec Kit feature that only polishes or corrects
  something already delivered (e.g. a renamed menu item, a layout tweak after a table test) is a `fix:`.
- Commit messages are written to a file and committed with `git commit -F` (Portuguese summary line after the prefix,
  the feature number in parentheses, e.g. `feat: ação repetida e menu da peça mais compacto (099)`).
