# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project status

The backend (feature `001-backend-core-entities`) is implemented in `backend/`; the frontend does not exist yet. There is no PostgreSQL or Docker on the dev machine, so migrations are generated but must be applied against a reachable database (`dotnet ef database update`, see below). Image URLs need S3 credentials (standard AWS env vars/profile) because reads generate presigned URLs.

## Product intent

Roll6 is a deliberately **simple** Roll20-style virtual tabletop web app. Scope:

- User login.
- Users create adventure maps.
- Users upload images (map backgrounds, token art).
- Users create tokens and place/move them on the map.
- Maps use a grid built with the hexagon algorithms from Red Blob Games: https://www.redblobgames.com/grids/hexagons/

Keep it simple — resist adding Roll20 features (dynamic lighting, character sheets, macros, chat, etc.) unless a spec explicitly asks for them.

## Constitution

`.specify/memory/constitution.md` is binding and overrides agents/skills when they conflict. Read it before planning or implementing. Highlights that are easy to get wrong:

- New entities MUST be built with the `dotnet-architecture` (backend) and `react-architecture` (frontend) skills — don't hand-roll those patterns.
- Frontend: Bootstrap 5 (not Tailwind/shadcn, even though the `ux-designer` agent defaults to them), Context API only (no Redux/Zustand), Fetch API for new services, `interface` over `type`, `VITE_` env vars.
- Directory casing is load-bearing: `Contexts/`, `Services/` uppercase; `hooks/`, `types/` lowercase.
- Never run `docker` / `docker compose` locally.
- PostgreSQL via EF Core only; snake_case tables/columns, `ClientSetNull` deletes (never Cascade).
- Auth token is stored in localStorage (never cookies); sensitive controllers need `[Authorize]`.

## Hex grid rules (Red Blob Games, constitution Principle VII)

All grid math must follow the Red Blob Games hexagon guide rather than ad-hoc formulas:

- Hexes are always **flat-top** in a rectangular grid (`grid_width` columns × `grid_height` rows, odd columns shifted half a hex down — the guide's "odd-q" offset layout).
- Positions are **stored as column/row** (`x`, `y`). For distance, neighbors, lines and ranges convert to axial (`q = x`, `r = y - (x - (x & 1)) / 2`), compute with the cube/axial formulas, and convert back (`x = q`, `y = r + (q - (q & 1)) / 2`). Never store `q`/`r`/`s`.
- Hex↔pixel conversion goes through a `Layout` (size, origin) as described in the guide's "Implementation" section.
- Pixel→hex uses fractional hex + **cube rounding** (`hex_round`); never round q/r independently.
- Distance, neighbors, line drawing (lerp + round), and ranges come from the guide's cube/axial formulas.
- Keep the hex math in one pure, framework-free module (frontend) so it can be unit-tested and, if the backend needs grid logic, mirrored 1:1 in C#.

## Backend layout and commands

Solution lives in `backend/` (`Roll6.sln`): `DTO` → `Infra.Interfaces` → `Domain` → `Infra` → `Application` (centralized DI in `Startup.cs`) → `API`, plus `Roll6.Mcp` (MCP gateway, depends only on `DTO`) and `Roll6.Tests` (xUnit + Moq + FluentAssertions, domain services only). Design docs: `specs/001-backend-core-entities/`.

- Users are local (`users` table, `PasswordHasher` PBKDF2); login issues our own JWT, sent as `Authorization: Bearer`, valid for **90 days** (`Jwt:ExpirationHours` = 2160 in every `appsettings*.json`; the frontend reads the `expiresAt` of the login response and logs out when it passes). Controllers take the owner id from the JWT `sub` claim (`CurrentUserId`) and pass it to services, which enforce ownership.
- Error flow: services throw domain exceptions and every controller action wraps its body in `try { } catch (Exception ex) { return HandleException(ex); }` (`ApiControllerBase`): `DomainValidationException` → 400 `ValidationProblemDetails`, `UnauthorizedAccessException` → 403, `KeyNotFoundException` → 404, `ConflictException` → 409, anything else → `StatusCode(500, ex.Message)`. Never throw `InvalidOperationException` for business conflicts — EF Core throws it on connection failures.
- Responses follow the ASP.NET Core default: DTO returned directly on success, `ProblemDetails` on errors (constitution v3.0.0). No custom envelope — ignore the `sucesso`/`mensagem`/`erros` shape in the `react-architecture` skill. Paged lists use `PagedList<T>` with `PageQuery` (`page`, `pageSize` ≤ 100, `search`).
- Images: stored in DigitalOcean Spaces through the AWS S3 SDK (`S3:ServiceUrl` = `https://{region}.digitaloceanspaces.com`, `S3:Region` = `us-east-1` signing region, `ForcePathStyle` false; empty `ServiceUrl` means AWS S3). For custom endpoints the client disables default checksums and chunked uploads, which S3-compatible providers may reject. Upload once via `POST /api/image` (`IImageStorageAppService`); files go to `{S3:Folder}/{guid}.{ext}` (`S3_FOLDER` in the env files, default `roll6`); entities store only `{guid}.{ext}` (validated by `Guard.ImageFileName`) and the storage service adds the folder, reads return presigned URLs. The bucket sends no CORS headers, so the map-share canvas reads stored images through `GET /api/image/file/{fileName}` (`[Authorize]`, name must be `{32-hex}.png|jpg|webp`, streamed from the bucket via `IImageStorageAppService.OpenAsync`; excluded from the MCP catalog) — `lib/mapSnapshot.loadImage` extracts the name from the presigned URL (`storedImageName`) and only falls back to a direct `crossOrigin` load for other URLs. Character sheet files (feature 022) use `POST /api/document` (`DocumentController` → `IImageService.UploadDocumentAsync`): PNG/JPEG/WebP **or PDF** (signature `%PDF-`), ≤ 10 MB, bytes stored untouched with the original Content-Type, response `{ fileName, url, type: image|pdf }`; `characters.sheet_file` holds the name (`Guard.SheetFileName`, `.pdf` allowed only there), sent as `sheetFile` in `POST`/`PUT /api/character` (omitted on PUT = removed) and read as `sheetFileUrl`/`sheetFileType` (`SheetFiles.TypeOf`) in `CharacterInfo`. Since feature 032 each participation has its own `campaign_characters.sheet_file`, copied from the character when it joins and read as `sheetFile`/`sheetFileUrl`/`sheetFileType` in `CampaignCharacterDetailInfo` (owner, master, approved participants) — stored files are write-once `{guid}.{ext}` and nothing ever overwrites or deletes them, so the campaign "copy" is a second reference to the same object, not a second blob (that is also what makes replacing or removing one side leave the other untouched).

- MCP server (feature 020): separate project **`Roll6.Mcp`** (own container `roll6-mcp`, `Roll6.Mcp/Dockerfile`, dev `dotnet run --project Roll6.Mcp` on http://localhost:5129) exposing the API to AI assistants at `/mcp` (Streamable HTTP, `ModelContextProtocol.AspNetCore` 2.x). It is a **thin gateway**: it references only `Roll6.DTO` and holds no database, S3 or JWT secrets — every tool is one REST call to the API (`Roll6Api:BaseUrl`, `http://api:8080` in containers) through `Roll6ApiClient`, which forwards the caller's `X-Api-Key` (or `Authorization`), so permissions, validation, results and the real-time events (017) are the API's. `ApiCredentialGate` answers 401 on `/mcp` without a credential the API accepts (checked via `GET /api/user/me`, cached 60 s). `McpToolRunner.FromResponseAsync` turns the API response into the tool result: JSON as text + `structuredContent` (lists inside `{ items }`, 204 → `{ ok: true }`), errors → `isError` with the API's problem details (plain-text/empty bodies get `status`/`detail`). Each tool (`Tools/*.cs`, `[McpServerToolType]`) carries `[ApiOperation("VERB", "/api/route")]`, an English `[Description]` with *What it does / Who can use it / Returns / Common errors / Related tools*, described parameters (`McpDocs`) and `ReadOnly`/`Destructive`/`Idempotent` annotations; `Roll6Guide` is the resource `roll6://guide`, the tool `get_roll6_guide` and the server instructions. **Adding or changing an endpoint requires its tool**: `Roll6.Tests/Mcp/McpCoverageTests` (every controller action except the 8 login-only ones has exactly one tool), `McpRouteParityTests` (each tool sends its `ApiOperation` verb/route with the caller's key, via `FakeApi`) and `McpDescriptionTests` guard it. Client setup: `claude mcp add --transport http roll6 https://{domain}/mcp --header "X-Api-Key: r6_…"`. The `web` nginx proxies `/mcp` to `mcp:8080`; the Vite dev server to `VITE_MCP_PROXY` (5129).
- `Roll6Context` configures every table inline in `OnModelCreating`; add one migration per change. The Npgsql legacy timestamp switch is on because columns are `timestamp without time zone` holding UTC. Int columns with DB defaults need `HasSentinel` so explicit zeros are persisted.

The renderer is a **Wolfenstein 3D raycaster**: `lib/raycaster.ts` (pure: `buildMaskGrid` reads the mask's **tones into a grid of wall heights** — the **median** luminance of each cell's own pixels, 0–255, never the average, which would make half-height walls out of the softened edges of an old black and white mask; ≤ 512 cells over the map image's area; `castRay` is the DDA and returns the **list of faces** near to far, keeping only a cell taller than the tallest seen so far, ≤ `MAX_FACES_PER_RAY` = 8, stopping at a wall of full height, so a low wall does not block the view; perpendicular distance, `wallColumn(…, height)` — a wall shorter than the eyes has its top **below** the horizon, `floorPoint` floor casting, `skyColumn`/`skyRepeats` panorama, `projectSprite`) and `lib/raycastFrame.ts` (pure: `drawRaycastFrame` fills an RGBA frame column by column — **sky above the horizon and floor below it as the base, then the faces from the farthest to the nearest**, so over the top of a mureta one sees the wall behind and between its top and the horizon the ground behind it; the floor is only computed in the rows no wall paints; then the figures far to near, occluded **row by row** by `ColumnWalls`/`hiddenFrom`/`hiddenAt`, which replace the old one-distance-per-column z-buffer) are unit-tested; it returns `FrameResult` (`frameWidth`/`frameHeight` and, per figure drawn, `id`, `screenX`, `top`, `bottom`, `depth`, `headVisible`) for the balloons. `components/story/raycastRenderer.ts` only puts the frame (≤ 480 columns) on the canvas without smoothing, calls `onFrame(result)` after each redraw and has `refresh()` to draw again (a new saying). World units are map pixels, figures stand at `hexCenter` (no hex math in the raycaster). Walls take the colors of the **map image** where the ray hits them — or, with the map's **wall texture** (036: `draft.wallTextureImage`, uploaded in the "3D" tab of `ImageModal` and in "Editar mapa", read by `StoryView` at ≤ 1024 px and handed to `raycastRenderer.setWallTexture`), the picture, laid on the face by the pure `lib/wallTexture` (a whole wall is as tall as the picture, so a low wall shows its lower part; it repeats along the wall every `WALL_HEIGHT × width/height` units, column from the hit's x or y by face side, row from the height of each screen row), shaded by distance like the colors; a transparent texel falls back to the wall color and the top of a low wall keeps the map image — and the **floor goes on past the edge of the image** with the color of its nearest edge (036, `clampedMapIndex`): no black band and no seam, and a transparent pixel or no image is the neutral color; the background turns with the camera and stays still when walking. Figures are only the pieces **standing** (`lib/pieceDrawing.isShownIn3d`: a piece that is down or out of combat, or whose token has no "2,5D" front image, is not drawn in 3D and its speech balloon is not shown either, though the 2D map still shows it lying and the camera can still follow its character), built by `spriteSpec` (`views`: the token's four "2,5D" URLs, `fallbackUrl`: its standing image, plus the piece's `look`); `StoryView` reads each URL once (a cache keyed by URL, a failed read resolving null so one bad image never drops the figures) and `drawRaycastFrame` picks, **every frame and per figure**, the side the camera sees — `lib/spriteView.viewSeen(look, piece, camera)` (front ±45° of the facing, back ±45° of the opposite, the two sides in between, an exact border going to front/back, `1e-9` tolerance; "right"/"left" are the character's own sides) and `chooseSprite` (a side without its image draws the **opposite one mirrored** — the texture column is inverted; a missing back draws the front, never mirrored; no front draws the standing image), so the figure keeps its size, its place on the floor and the wall occlusion (row by row since 036: above the top of a nearer low wall the figure still shows) and only the drawing changes. The form state of the four images is `hooks/useSpriteImages` (crops + which saved images are kept, reset when the modal opens or the token changes), saved through `lib/spriteView.resolveSpriteImages` (uploads only the sides with a new crop) and `toTokenInsert(form, up, down, sprites)`. The camera (`lib/storyCamera.ts`, `hooks/useStoryCamera`) only turns sideways (no tilt), is third person behind the chosen character's piece and follows it while attached, any input lets go ("Voltar ao personagem" reattaches), GM/no piece → free at the center, never inside a mask wall (any wall, however low — `isWallAt` is height > 0) nor off the map, zoom = FOV 30–90°, touch `VirtualJoystick`. **Speech balloons of the turn in progress show over the 3D figures** (036): `StoryView` reads `useTurn().entries`, takes the last action of each actor with `lib/turnStatus.lastActions` + `pieceKey` (the same text the 2D map shows, only for the pieces `isShownIn3d`) and hands them to `components/story/BubbleLayer`, an HTML layer over the canvas (`pointer-events: none`) that on each `onFrame` places every balloon with `lib/storyBubbles.bubblePlacement` (`scale = clamp(REFERENCE_DEPTH / depth, 0.7, 1.2)`, kept inside the canvas with `SCREEN_MARGIN`, hung under the head when it does not fit above it, `null` when the head is not visible) and `orderByProximity` (nearer = larger z-index), writing `left`/`top`/`transform`/`zIndex` straight into the DOM — no React render per frame, and the same look as the 2D balloon (`.stm-story-bubble`, up to three lines, `story.bubbleLabel` in `title`/`aria-label`). A balloon disappears with its figure: down, out of the frame or behind a wall. The user only observes: nothing in the 3D view moves a piece. No 2D canvas → toast `story.noWebgl` and back to 2D.
