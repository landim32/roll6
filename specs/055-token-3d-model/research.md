# Research: Modelo 3D no token e caminhada em terceira pessoa

The spec has no open clarification (Q1 = C: the walk is local; Q2 = A: clips from the file, Roll6's own for a Mixamo skeleton, else static). The decisions below map it onto the raycaster of 034/036/053.

Reference file: `orc-gordo.glb` (generator "Tripo") — 4.7 MB, 1 skinned mesh, 7 842 triangles, 1 material with 3 embedded textures, 1 skin of 44 joints named `mixamorig:*` (`Hips`, `Spine…Spine2`, `Neck`, `Head`, `Left/RightUpLeg`, `Leg`, `Foot`, `ToeBase`, `Shoulder`, `Arm`, `ForeArm`, `Hand`, fingers), **no animations**, bounds x ±0.5, y 0…0.90, z ±0.16 (glTF units, feet at y = 0, Y up), extensions `KHR_materials_volume`, `FB_ngon_encoding` (both optional, ignorable).

## R1. How the 3D view draws a skinned mesh

- **Decision**: bring back **`three`** (r0.186, the version 033 used, + `@types/three` dev), loaded **only** through dynamic imports: the model layer of the 3D view (imported by `StoryView` only when some standing piece on the map has a model) and the preview of the token form (lazy component). The raycaster stays the renderer of walls, floor, sky and 2,5D figures; a transparent **WebGL canvas** over it draws the models with the same camera.
- **Rationale**: skinning, glTF parsing (`GLTFLoader`), animation blending (`AnimationMixer`) and texture sampling are exactly what three.js does and what a Canvas 2D raycaster cannot do at an acceptable cost. Keeping the raycaster avoids redoing 034/036/053 (masks with heights, wall texture, quality levels, the byte-pinned reference frame) and keeps maps without models on the exact code path of today (no new chunk loaded, SC-004).
- **Alternatives considered**: migrating the whole 3D view to three.js — rejected: the 036 tone-height walls, the wall texture mapping and the pinned reference frame would all have to be re-implemented and re-verified, for no gain to the spec. Software skinning in Canvas 2D — rejected: per-pixel triangle rasterization of ~8 k skinned triangles per model per frame in JS is far too slow on phones. `@react-three/fiber` — rejected: another dependency and a React render loop where the 3D view writes straight to canvases outside React (036 balloons rule).

## R2. Matching the raycaster's camera and its occlusion

- **Decision**: world mapping three.js `X = map x`, `Z = map y`, `Y = up` in map units; the `PerspectiveCamera` sits at `(pose.x, EYE_HEIGHT, pose.z)` looking along `forwardOf(pose.yaw)` (no tilt), with vertical FOV derived from the raycaster's horizontal FOV and the frame aspect (`vfov = 2·atan(tan(hfov/2)/aspect)`). Walls occlude models through **depth-only geometry** built from the same `MaskGrid`: one box per wall cell (`InstancedMesh`, `colorWrite: false`), `height = heights[cell] / 255 × WALL_HEIGHT`, drawn before the models. Nothing else is drawn in WebGL (no floor, sky or walls in color).
- **Rationale**: the raycaster is a pinhole projection with square pixels, so a matching perspective camera puts a model exactly where a sprite with the same foot point would be; a unit test projects reference points with both (`projectSprite` vs. a pure `lib/modelCamera` matrix) to pin it. Depth-only boxes from the cells reproduce the row-by-row occlusion of 036 (a low wall hides only the lower part of the model) without reading the raycaster's frame.
- **Alternatives considered**: reading the raycaster's per-column wall data into a depth texture — more exact at cell corners but needs a custom shader and a texture upload per frame; boxes are static per map. Drawing models into the raycast frame (render-to-texture + readback) — a GPU→CPU readback per frame, too slow.

## R3. Resolution and the quality levels (053)

- **Decision**: the WebGL canvas covers the 3D view and is stretched with `image-rendering: pixelated`. Its drawing buffer is the **frame size** (`profile.columns` × rows) on Padrão and Alta and the **screen size** on Ultra — the same rule as the 2,5D figures (inside the frame on Padrão/Alta, on a screen-size layer on Ultra). The raycaster is untouched: `raycastFrame.test.ts` stays byte-identical.
- **Rationale**: a model in Padrão looks as chunky as the walls around it; Ultra gets sharp models like it gets sharp figures (spec edge case "Qualidade do 3D").

## R4. Fallback while loading, on failure, and the balloons

- **Decision**: a piece whose token has a model stays in the raycaster's sprite list as a **proxy**: until its model is ready (or when it failed), it is drawn exactly as today (2,5D sides → standing image → initial placeholder); once the model is drawn, the proxy gets `hidden: true` (new optional field of `RenderSprite`) and is **not painted**, but `drawRaycastFrame` still reports it in `FrameResult.figures` (screen position, depth, `headVisible`). `BubbleLayer` keeps working unchanged. `isShownIn3d` becomes "standing and (front image or model)".
- **Rationale**: FR-005 (never nothing), FR-007 (balloons over the head, occlusion of the head), SC-006 (a failure never breaks the view). The model is fitted to the proxy's height (R5), so the head the raycaster reports is where the model's head is.
- **Alternatives considered**: projecting heads with three.js and a second occlusion test — duplicates `hiddenAt`.

## R5. Size, feet and facing of a model

- **Decision**: pure `lib/modelFit.ts`. Bounds come from the skinned mesh in its bind pose. **Height** = the height of the silhouette of the piece's 2,5D figure: `SILHOUETTE_SHARE × width / FRONT_IMAGE_ASPECT` where `width` is the `spriteSpec` width of the piece's shape (1 hex ≈ 64 units, like a figure fitted to the crop's silhouette). Uniform scale = height / bounds height; the model is moved so the middle of its feet (bounds min y, center x/z) stands on `spriteSpec.center`. **Facing**: glTF "forward" is +Z; the model is turned so +Z points along `forwardOf(lookToYaw(look))` (pieces) or the walker's yaw. Models lying on their side are not corrected (spec assumption: no manual adjustment in this version).
- **Rationale**: same size and place as the sprite it replaces (spec edge "Tamanho do modelo"), feet on the floor whatever the file's scale (the orc is 0.9 units tall, others are in cm).

## R6. Animations: clips from the file, Roll6's own for a Mixamo skeleton (Q2 = A)

- **Decision**: pure `lib/modelAnimations.ts` decides, per state, the source: `file` when a clip name matches (case-insensitive, after stripping any `Armature|`-like prefix: idle = `idle|parado|stand|breath`, walk = `walk|caminh|andar`); else `roll6` when the skeleton is **Mixamo-like** (bones `Hips`, `Spine`, `Head`, `LeftUpLeg`, `LeftLeg`, `RightUpLeg`, `RightLeg`, `LeftArm`, `RightArm` present, names compared after removing a `mixamorig[0-9]*:` prefix); else `static`. Roll6's clips are **data** in `lib/roll6Clips.ts`: for each state a loop (idle 3 s, walk 1 s) of keyframes per bone given as rotations in the **character's frame** (axis-angle about character X/Y/Z, plus a small Hips height offset as a fraction of the model height), so they don't depend on each bone's local axes. `components/story/threeClips.ts` turns them into a `THREE.AnimationClip` per model: for each bone, `local = parentWorldRest⁻¹ · delta · parentWorldRest · localRest` (the delta expressed in the bone's parent space at rest), sampling the same keyframe times. Idle = breathing (spine/chest ±2°, shoulders, head sway, arms slightly out); walk = legs ±25° at the hips and knees bending, arms counter-swinging ±15°, hips bobbing, spine twist ±4°.
- **Rationale**: Mixamo naming is what the example file and the common auto-riggers (Tripo, Meshy, Mixamo itself) produce; expressing the motion in character space makes it work whatever rest orientation the rigger gave each bone. Pure data keeps it unit-testable (loop closes, amplitude limits, every Mixamo bone known).
- **Alternatives considered**: shipping Mixamo FBX/GLB animation files and retargeting — license and file size, and still a retargeting step; requiring clips in the file — rejected by the clarification.
- **Blend**: one `AnimationMixer` per drawn model; idle ↔ walk cross-fade of 0.25 s (FR-009 < 1 s). Pieces of other people are always idle (the walk is local, Q1 = C).

## R7. Walking in free mode (local only, Q1 = C)

- **Decision**: pure `lib/walker.ts`: `WalkerState { x, z, yaw, moving, distance }` starting at the piece's center and `lookToYaw(look)`; `stepWalker(state, input, dt, blocked)` turns with left/right (`TURN_SPEED` of today), walks with forward/back at **1.5 hex/s** (`WALKER_SPEED = 1.5 × √3 × HEX_SIZE` ≈ 104 px/s, the distance between two hex centers being √3 × size), slides along obstacles one axis at a time like `stepCamera`; strafe keys turn too (no side-stepping, the model would moonwalk). `walkerBlocked` = `cameraBlocker` (mask walls of any height + map edge, radius `HEX_SIZE / 3`) **plus** the hexes taken by the other pieces' footprints (`lib/occupancy`, the walker's own piece excluded; the point is converted with `pixelToHex`). Camera: `walkCamera(state, blocked)` = `followPose` generalised to a continuous yaw and a distance in `[1.5, 8] hex` (`WALK_DISTANCE_MIN/MAX`, default `FOLLOW_DISTANCE`), changed by the zoom buttons/wheel/pinch in steps; the FOV stays at its value. `useStoryCamera` gets a `walk` mode: while on, every movement input goes to the walker and the camera is always attached (no "Voltar ao personagem").
- **When it is on** — pure `canWalk`: free mode, the viewer has a chosen approved character, its piece is on the open map and `isShownIn3d` (standing), and the viewer is not acting as the GM. The model may be missing: a piece shown as a 2,5D figure walks too (its proxy just moves; no animation).
- **Reset** (FR-013/FR-014): the walker is dropped and rebuilt from the piece when free mode turns off, the piece's `x`/`y`/`look` or posture change (realtime `mapToken.upserted`), the map or the chosen character changes, or the 3D view unmounts. Nothing is sent anywhere; `MapTokenService` and the turn are not touched.
- **Rationale**: Q1 = C; SC-003 (same keys and joystick as today).

## R8. Storing and serving the file

- **Decision**: `POST /api/model` (`ModelController`, `[Authorize]`, `[RequestSizeLimit(21_000_000)]`) → `IImageService.UploadModelAsync` stores the bytes untouched (`model/gltf-binary`, extension `glb`, `{S3:Folder}/{guid}.glb`) after checking: ≤ 20 MB, header `glTF` magic (`0x46546C67`), version 2, header length = file length, first chunk type `JSON`. Response `{ fileName, url }`. The token keeps `tokens.model_file varchar(260) null` validated by `Guard.ModelFileName` (`^[0-9a-f]{32}\.glb$`). The bucket sends no CORS headers, so the browser reads the model through **`GET /api/model/file/{fileName}`** (`[Authorize]`, name must match the guard, streamed from the bucket via `IImageStorageAppService.OpenAsync`, `Cache-Control: private, max-age=31536000, immutable` because stored names are write-once), with the session token, exactly like `GET /api/image/file/{fileName}`; it is excluded from the MCP catalog.
- **Rationale**: same pattern as images (upload once, name in the entity, presigned URL in reads) and as the 041 audio (signature check, stored as is). The proxy is what makes `fetch` work without CORS.
- **Alternatives considered**: storing models through `POST /api/document` — its type list and 10 MB limit belong to sheets; a separate route keeps errors precise ("Envie um arquivo .glb").

## R9. Token contract

- **Decision**: `Token.ModelFile` + `Token.UpdateModel(string? modelFile)` (separate from `Update`/`UpdateSprites`, like 035). `TokenInsertInfo.modelFile` (the PUT replaces every field: omitted = removed, so the form sends back the stored name — the same rule as the 2,5D images); `TokenInfo.modelFile`/`modelFileUrl` (presigned); `MapTokenInfo.modelFileUrl` (piece's token). Only the token's creator edits it (existing `TokenService` rule).
- **MCP**: new tool `upload_token_model` (`POST /api/model`, base64 like `upload_document`, ≤ 20 MB binary), `modelFile` on `create_token`/`update_token`, the guide's "3D view" section gains the model, the Mixamo rule and the local walk. Counts **102 operations / 103 tools**.

## R10. Preview in the token form

- **Decision**: a third tab **"3D"** in `TokenFormFields` (kept mounted like "2,5D"), with `components/tokens/ModelField` (file input `.glb`, client check with `lib/modelFile.checkModelFile` — size, magic, version — then a lazy `ModelPreview`). `ModelPreview` (lazy, own small three.js scene: hemisphere + directional light, ground circle, the model fitted to a fixed height, slow turntable that stops while the user drags to rotate) plays idle, has a "Caminhar"/"Parar" toggle to preview the walk, and lists the source of each state (`tokens.model.source.file|roll6|static`), warning when static. The file is uploaded on save (like the 2,5D crops), not on pick; parse errors in the preview block saving with `tokens.model.invalid`. Viewers who are not the creator get the preview only.
- **Rationale**: FR-001/FR-002/FR-003/FR-015; parsing in the preview is the strongest validation the client can do without the server parsing glTF.
